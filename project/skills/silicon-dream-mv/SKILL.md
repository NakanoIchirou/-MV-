# 有限预算下的 MV 制作与修订

把作者意图落实为可审阅的影像。先证明关键表达做得出来，再扩展制作；把精力花在可见的缺陷和叙事效果上。

## 接手时先确定事实

- 找到用户当前指定的成片、工程、审片页和最近修改。磁盘当前内容优先于旧聊天路径；检查能否读到实际素材。不要把同名旧版本当基线。
- 《硅晶之梦》的归档入口、已选修改和重导出限制见 [项目接手参考](references/project-v25.md)，只在处理本项目时读取。
- 判断任务属于新制作、局部修改、审片评论还是归档。评论只输出评价；局部修改只影响相关镜头及必要接缝；归档不触发重渲染。
- 用户已经明确的画风、分镜、帧率形式、工具限制及预算继续有效。只有缺失信息会改变实际结果时才提问。

## 先做一个能证明方案的样段

新制作或更换技术路线时，选择一个最难动作和一个关键转场，做低成本样段，验证空间关系、主体一致性及运动方式。样段过关后再铺开。

工具能力先以一次小规模实测确认。区分图像生成、图层变换、视频生成、后期剪辑和声音分析；没有可调用的 AE 插件就明确说明，不把 FFmpeg 操作称为 AE 制作。无法人工式听辨时，程序测到的节拍和波形只能作为分析证据。

先用粗剪验证整片时间分配：每段新增了什么信息，主题何时出现，重复是否在累积情绪。修正大结构的时机应早于精修线条。已锁定的时间轴只提出建议，未经用户要求不因审美意见擅自重剪。

## 固定美术和空间关系

- 建立最小基准：人物比例、识别色、物体位置、场景布局、行进方向和参考画。优先复用用户已选素材。
- 改观察角度时调整摄像机和构图，保持人物、门、楼梯、轨道等的合理空间关系。避免为了“看得清”移动物体或扭转人体。
- 区分合理的景别变化和无意缩放。同一连续动作中保持人物比例及场景锚点；不同尺寸图片统一适配到固定画布，避免每格自动裁切造成忽大忽小。
- 用户禁止新图时，使用现有素材、裁切、图层或局部数字替换完成授权修改；新增镜头或重画不能藏在“修复”里。

## 把时间轴写成唯一可执行记录

每镜至少记录：镜号、素材路径、起始输出帧、持续输出帧、画面形式和选用状态。定格镜增加格位编号、素材及停留帧数；音效记录落点和时长。

**输出帧率、画面更新频率、音乐拍子、定格格位是四个概念。** 60fps 导出可以承载每秒两次画面变化；八个格位可以复用四张图。不要把“删第一帧”直接解释成删掉 1/60 秒，先根据用户正在使用的编号体系判断，仍有实质歧义才问。

以整数输出帧累计时间，避免逐镜小数取整造成接缝和音频漂移。变更映射先写清，再生成：

- “第6格换成第4格”：确定引用的是修改前当前版本的第4格，只替换目标格的内容。
- “删掉首格，后面前移”：明确移动范围、跨镜边界及末端如何补齐；保持原片长时，记录补齐来自哪里。
- 倒计时：逐格列出值、停留和变灯位置，把音效落点与视觉变化对照；不要只检查首尾数字。
- “定格在前镜末帧”：从实际选用视频解码末帧，保留其尺寸和构图。黑屏、点击和片尾各用准确时间表示。

改动表和素材映射留在工程中，避免一轮修订后只能依赖聊天猜测。

## 动作和转场服务表达

定格是可选择的成片形式。用户已选择定格时按其形式验收，不因低帧率自动判成未完成；同时不得把定格交付称作连续动画。

每次换帧应带来可辨动作、视线变化或叙事信息。等待段需要节奏或细节变化支撑停留。长镜头、全流程展示和复杂变形都不是默认目标；清楚的切镜往往更适合有限素材。

检查转场中间态：边框、连线、肢体或物体在变形途中是否散开、重影、穿插。首尾正确不能证明过渡成立。同类问题反复发生时减少运动复杂度，改用可控的遮罩、切镜或短过渡；形式若受用户锁定，先交代限制并给出具体替代选择。

本项目的反例和审片尺度见 [制作复盘](references/lessons.md)。这些观察用于选择做法，不自动授权重剪已选镜头。

## 审片检查实际导出

按当前修改的风险选择检查，不把每次数字替换扩大成全片重做。

1. **技术层**：尺寸、编码、实际帧数、音轨、时长及可解码性。检查累积时间和接缝有没有多帧、少帧或意外黑帧。
2. **画面层**：查看实际输出的首、中、尾、每个状态变化及镜间边界；运动复杂处检查更密的连续帧。抽帧只能证明所看帧的情况，不冒充完整播放审阅。
3. **视听层**：在可实际播放的环境检查节拍、音效、动作和停留感。只有静帧/数据证据时说明限制，不凭波形声称音乐情绪或混音听感合格。
4. **作者选择**：分别记录 `technical_pass`、`visual_review`、`user_selected`，注明版本。导出成功不代表用户认可；用户认可也不等于文件不存在技术问题。

逐镜审片页显示镜号、当前版本、时间位置和实际选用画面，能跳转及定位意见。主片默认不烧入审片编号。页面使用归档内相对路径，并核对资源引用。

硬伤优先修：主体突变、错误动作、错号、接缝错位、明显断裂、音效落点错误。微小线条差异不能成为无限返工的理由。风格偏好和作者明确选择不计为硬伤。

## 控制返工和调度成本

默认由一个执行者维护时间轴和最终导出。仅在用户要求或其他适用指令明确要求代理协作时拆分可独立镜头；给定输入、约束、输出和完成证据，一处统合选用状态。不要让多个代理同时修改同一工程或互相审核却无人交付。

同一失败重复出现时暂停批量重试，先判断是素材、映射、工具能力还是表达方式的问题；一次最小验证后再决定继续。用户说停止画图或额度紧张时，立即收敛到已有资产和最小可行修改。

## 交付、存放和归档

- 本用户所有新文件及可配置缓存放 D 盘。运行工具前设置 TEMP、TMP、TMPDIR 和相关缓存路径；Node/Remotion 在加载库前设置。允许读取 C 盘已安装工具。
- 已选基线保留，候选独立存放；仅渲染改动镜头，再合并未改镜头，避免累计有损转码。保留无损混音及独立音效。
- 交付可用的成片链接、逐镜审片入口，以及本轮实际改动与未解决限制。用户只要求审阅时，导出不等于获准上传平台。
- 归档保留实际使用的素材、剧本、时间轴、原曲/混音、逐镜片段、成片和可重导出说明。只有 PNG 首尾图无法恢复原有连续运动，需保留原视频。
- 删除旧工程须有明确授权和范围。先检验归档在不依赖旧目录时可重导出、页面引用有效、文件校验一致，再清理已确认目录。不要顺带删除应用状态或其他项目。
- 已有校验清单的归档新增内容时，先验证旧基线，再更新清单；不能用重新生成清单掩盖意外改动。
